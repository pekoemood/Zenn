HTTParty gemの使用方法について

railsで使用する場合はまずincludeする
#include HTTParty

次にbase_uriを設定する
設定するbase_uriはエンドポイントの手前までがよい
エンドポイントはAPIによって変動するため、エンドポイントまで
含めてbase_uriを設定してしまうと柔軟性に問題が出る。

#geminiの場合は。。
base_uri 'https://generativelanguage.googleapis.com/v1beta/models'

次に initializeを設定する
ここでクエリの内容を設定してもよい
@options = { query: {key: @api_key}}など
ただし、initializeは基本設定に留めるべきなのでgeminiの場合は以下の通りとした

def initialize
  @api_key = Rails.application.credentials[:gemini][:api_key]
  ＃credentialsにアクセスする方法
  @prompt = prompt
end

次にAPIを叩くメソッドを実装するgeminiではpostメソッドで送信するため
headersやbodyを設定する必要があることに注意する

def generate_content
  options = {
    query: {key: @api_key},
    headers: { 'Content-Type' => 'application/json},
    #ここでkeyをシンボルにしていない理由は-が含まれるため、
    　-はシンボルで認識できないので、ロケットハッシュを使用する
    body: {
      content: [{
        parts: [{ text: @prompt}]
      }]}.to_json #to_jsonでJSON文字列に変換する　　　　　　　　　　
  }　＃ここにto_jsonとしないように注意するここにメソッドをいれると
  　　　ハッシュ全体をjson形式にしてしまうHTTPartyではハッシュで送信する必要がある


  response = self.class.post('/gemini-2.0-flash:generateContent', option)
  これでresponse変数に値を代入する。なお、最初の引数がエンドポイントになっている

  if response.code == 200
  formatted_response(response.parsed_response.deep_symbolize_keys)
  #formatted_responseはprivateメソッド、必要値を整形している
  　HTTPartyではparsed_responseでJSON.parseの結果を返してくれる。
  　また、deep_symbolize_keysで symbolize_names: trueと同じ結果を返してくれる

  else
    { error: 'API request failed', status: response.code }
  end
end

private
  def formatted_response(response)
    response[:candidates][0][:content][:parts][0][:text]
  end
  #このような整形はサービスクラス内に実装する
  　コントローラーに入れるとfatControllerになるので注意
