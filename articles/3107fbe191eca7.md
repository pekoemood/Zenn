2月4日の学び

ログイン機能をgemを使用せずに実装した
大まかな実装の流れは以下の通り

Userモデルを作成する
has_secure_passwordを設定して
password_digestをカラムとして登録する
さらにbcryptのgemがないと使用できないので、注意

次にUsers controllerを作成する
Usersは主にユーザーの新規登録を行う
newとcreateアクションのみ登録する

次にログイン、ログアウト機能としてSession controllerを作成する
アクションは new create destroyを用意する

ログインには　authenticate_byメソッドを使用した
user = User.authenticate_by(email: params[:email], password: params[:password])
で認証を行う
認証されたら session[:user_id] = user.idでid情報をsessionに登録する。なお、[:user_id]は自由に決めてよい

ログアウトする際にはdestroyアクションでreset_sessionで全てのsessionが破棄される


flashとnotice,alertについて
flashは主にredirect_toやrenderされた際に使用するメソッド
メッセージをviewに表示することができる

よくあるのはログイン成功を知らせるためにcontorollerに以下のようにコードする
flash[:notice] = 'ログインが成功しました’
しかし上記のコードは冗長、基本的には以下の通りコードする
redirect_to root_path, notice: 'ログインに成功しました’
これと最初のコードは全くおなじ動き、下の方が見やすい

しかし、renderの場合は以下のようにコードする
flash.now[:alert] = 'ログインに失敗しました’
render :new, status: :unprocessable_entity

flash.nowにしないとログインしてもそのままflashが表示されてしまうので、注意

最後にbefore_actionについて
ApplicationControllerでログインチェックフィルターを以下のようにかける

before_action :check_logined　　User,Sessionコントローラーでは skip_before_action :check_loginedを設定すること
helper_method :current_user helper_methodでviewでも指定したメソッドを使用できる

private
  def check_logined
    @current_user = User.find_by(id: session[:user_id])
    if @current_user.nil?
      resert_session
      flash[:referer] = request.fullpath　これで元々リクエストしていたpathが取得できるので、ログイン後に直接そのページに飛ばせる
      redirect_to login_path, alert: 'ログインしてください’
    end
  end

  def current_user
    @current_user ||= User.find_by(id: session[:user_id])
  end
end

current_userを使用することでveiwでログイン、ログアウト、新規登録をログイン状態とログアウト状態で表示、非表示を切り替えられる
<% if @current_user %>
  ログイン状態の表示
<% else %>
  ログイン、新規登録を表示する
<% end %>

f.hidden_field :referer, value: flash[:referer]
これで元々ログインしていた情報をformから飛ばせる
